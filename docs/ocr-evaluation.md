# PaddleOCR を Android で動かす検証

検証日: 2026-10-17 ／ 関連: #14（テキストらしい領域の簡易判定）、[今後のアイデア](ideas.md)

PaddleOCR（PP-OCR）を Android 端末内で動かせるか、日本語を読めるか、速度とアプリサイズへの影響を確かめた。
再現手順は [tools/ocr-eval](../tools/ocr-eval/README.md)。

## 結論

- **Android の端末内で動く。** PaddleOCR 公式の Android SDK（ONNX Runtime + OpenCV、Kotlin）で、ネットワークなしに検出・認識できた。
- **日本語を読むなら PP-OCRv6 small。** 架空の名札・宛名・小さく写った書類をすべて正しく読め、文字のない写真では何も検出しなかった。
- **PP-OCRv6 tiny は日本語を読めない。** 認識用の辞書にひらがな・カタカナがない（6,902 文字、中国語・英字中心）。ただし文字の位置の検出は正しく、最も速い。「テキストらしい領域」の判定だけなら候補になる。
- **公式 SDK はそのままでは Android 12 以降で動かない。** 依存する OpenCV（quickbirdstudios 4.5.3）の arm64 版が読み込めない。OpenCV 公式の Maven 版（`org.opencv:opencv:4.10.0`）へ差し替えると動いた。
- **アプリへの影響は APK +約 41MB（arm64）。** 検出だけ（tiny）なら +約 17MB。

## 方法

- 端末: Android Emulator（Pixel Tablet、API 31、arm64、RAM 6GB）。ホストは Apple Silicon Mac。
  **実機の速度ではない。** 実機（Xiaomi 14T Pro など）での計測は未実施。
- SDK: PaddleOCR `deploy/ppocr-android`（コミット `dab3fe3`）。ONNX Runtime 1.21.1、OpenCV 4.10.0 に差し替え、4 スレッド。
- モデル: Hugging Face の公式 ONNX（PP-OCRv6 small / tiny、PP-OCRv5 mobile）。リビジョンと SHA-256 は `tools/ocr-eval/run.sh` に固定。
- 画像: 架空の個人情報を描いた 1200×1600 の JPEG を 4 枚（`tools/ocr-eval/make_images.py`）。
  1. 斜めの名札 2. 宛名ラベル（少しぼかし） 3. 部屋の写真の隅に小さく写った書類（傾き・ぼかし） 4. 文字のない写真
- 検出前の縮小: 公式の既定（実質等倍）と、長辺 960px の 2 通り。各画像 2 回のウォームアップ後、5 回の中央値。

## 結果

### 認識結果（長辺 960px）

| 画像 | 正解 | v6 small | v5 mobile | v6 tiny |
| --- | --- | --- | --- | --- |
| 名札 | 株式会社カメレオン / 営業部 / 山田 花子 | すべて正解 | すべて正解 | 「株式会社力×L才>」「當業部」 |
| 宛名 | 〒150-0002 / 東京都渋谷区渋谷1丁目2-3 / カメレオンビル5F / 佐藤 太郎 様 | すべて正解 | 〒 を「=」と誤認 | 渋→浅、カタカナ全滅 |
| 小さい書類 | 請求書 / 鈴木 一郎 様 / 090-1234-5678 | すべて正解 | すべて正解 | 請→请 |
| 文字なし | なし | **検出なし** | 誤検出 2 件（低スコア・空文字） | 誤検出 2 件（低スコア） |

- v6 small・v5 mobile とも、名前の間のスペースは落ちることがある（「佐藤太郎様」）。隠す用途には影響しない。
- 等倍で検出すると、v6 small も文字なし画像で大きな誤検出を 3 件出した。縮小した方が誤検出が少なく速い。
- 誤検出は、空文字・記号 1 文字・スコア 0.6 前後以下のどれかだった。スコアのしきい値と文字数で除ける見込み（v5 mobile には「•」をスコア 0.65 で出した例がある）。
- 検出枠はどのモデルでも文字の位置と一致した（名札の傾きも追従）。

### 処理時間（ミリ秒、エミュレーター）

2 回計測した範囲。エミュレーターのため実行ごとに 1.5〜2 倍ほど揺れる。

| モデル | 縮小 | 検出 | 認識 | 合計 | 初回読み込み |
| --- | --- | --- | --- | --- | --- |
| v6 small | 長辺 960 | 200〜360 | 45〜145 | 205〜460 | 200〜400 |
| v6 small | 等倍 | 580〜1,130 | 20〜170 | 620〜1,210 | 230〜310 |
| v5 mobile | 長辺 960 | 150〜490 | 55〜440 | 170〜1,070 | 190〜1,410 |
| v6 tiny | 長辺 960 | 110〜160 | 5〜35 | 125〜190 | 55〜70 |

撮影後に 1 回かける用途なら、v6 small・長辺 960 で 0.5 秒以内に収まる見込み（実機で要確認）。
プレビュー中に毎フレームかけるのは重い。tiny の検出だけを間引いて回すのが現実的。

### サイズ（arm64、APK 内の圧縮後）

| 項目 | 元のサイズ | 圧縮後 |
| --- | --- | --- |
| ONNX Runtime | 18MB | 6.4MB |
| OpenCV | 21MB | 8.4MB |
| libc++_shared | 1MB | 0.3MB |
| v6 small 検出モデル | 9.4MB | 7.6MB |
| v6 small 認識モデル | 20MB | 18.5MB |
| v6 tiny 検出モデル | 1.7MB | 1.6MB |

- v6 small で検出＋認識: +約 41MB。インストール後の容量は +約 70MB。
- v6 tiny で検出だけ: +約 17MB。
- OpenCV は画像の読み込み・縮小・切り出し・輪郭抽出にだけ使っている。置き換えれば約 8MB 減らせる。
- 現在の APK（universal）は約 47MB。

## 気づいたこと

- 公式の OpenCV 4.5.3 の arm64 ライブラリは `__sfp_handle_exceptions` を参照しており、API 31 のエミュレーターで `dlopen` に失敗した。Android 16 の実機でも同じと見られる。
- 公式 SDK の minSdk は 26（Android 8.0）。camereon は現在 24（Android 7.0）。組み込むなら minSdk を 26 に上げる必要がある。
- 公式の既定（`detLimitType = "min"`、短辺 64）では画像をほぼ等倍で検出するため、RAM 2GB のエミュレーターでは v6 small でメモリ不足になりプロセスが落ちた。縮小して検出すべき。
- Gradle 8.9 を使うため、ビルドには JDK 17〜21 が必要（JDK 25 では動かない）。
- モデルと SDK は Apache License 2.0。
