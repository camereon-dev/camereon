# Gemma 4 E2B / SmolVLM2 の Android 検証

実施日: 2026-10-20。関連: [#23](https://github.com/camereon-dev/camereon/issues/23)。

ユーザーの方針に従い Gemma 3n は対象から外し、Gemma 4 E2B を主候補、SmolVLM2 500M を軽量比較用にした。
リスク評価の仕様・精度・統合ルールは [#24](https://github.com/camereon-dev/camereon/issues/24) で後続として扱う。

## 実施したこと

本体と独立した Flutter 評価 APK から、Android ARM64 エミュレーターで **両モデルのロード・画像入力・テキスト出力まで実行した**。
初回の比較では画像なし、赤い円、青い棒3本、英語の架空荷札を同じ質問で入力した。

| 確認事項 | 状態 |
| --- | --- |
| 依存・モデル | SDK バージョン、配布リビジョン・容量・SHA-256 を固定。ホスト・端末の双方でモデルを照合 |
| ビルド・静的解析 | Debug APK のビルド成功。`flutter analyze --no-pub` は指摘なし |
| 初回の単独画像推論 | Gemma 4 / SmolVLM2 とも画像なし1件 + 画像3件を完走 |
| 日本語の固定 OCR 補足 | 同じ日本語荷札・OCR データ・短い質問を両モデルに入力。下記の結果を取得 |
| オフライン | APK に `INTERNET` 権限なし。追加比較ではエミュレーターの機内モードも有効にした |
| Android 実機 | 未接続。実機の速度・メモリ・GPU 対応は未確認 |
| 本体への統合・リスク判定 | 未実施 |

## 環境と条件

- Flutter 3.47.7 / Dart 3.13.5、`flutter_edge_ai 2.4.1` / `flutter_edge_ai_litertlm 1.15.0`
- Android API 31 / ARM64 エミュレーター、RAM `8118916 kB`（起動設定 8 GiB）
- テキスト・画像エンコーダーとも実際のバックエンドは CPU
- Debug ビルド、context 2048、出力上限 160 tokens、temperature 0、topK 1、seed 42
- 各ケースで会話を新しく作成。画像 ID や正解文は画像単独の質問には渡さない
- 入力は独自の合成画像。通常の撮影画像の精度を測った実験ではない
- 初回とキャッシュ作成後の再実行を区別。OS ページキャッシュやホスト負荷は統制していない

手順・コード: [tools/vlm-eval](../tools/vlm-eval/README.md)。モデルの固定情報は [Gemma 4](../tools/vlm-eval/model.json) と [SmolVLM2](../tools/vlm-eval/smolvlm2.json)。

## 初回実行の結果

以下の時間はエミュレーター上の測定値。実機の速度・必要 RAM の保証には使わない。
モデルロードと画像推論時間は別。各画像の値は入力開始から出力完了まで。

| 項目 | Gemma 4 E2B | SmolVLM2 500M |
| --- | ---: | ---: |
| モデル容量 | 2,588,147,712 bytes | 360,822,960 bytes |
| モデルロード | 9.934 秒 | 1.668 秒 |
| 赤い円 | 18.388 秒 | 7.119 秒 |
| 青い棒3本 | 37.685 秒 | 10.388 秒 |
| 英語の荷札 | 78.986 秒 | 5.282 秒 |
| プロセスの最大 RSS | 2938 MiB | 1129 MiB |
| サンプリングした最大 PSS | 2805 MiB | 1025 MiB |

RSS は `ProcessInfo.maxRss`、PSS は約3秒おきの `dumpsys meminfo` からの最大値。PSS は瞬間的なピークを取り逃がしうる。
出力の長さが異なるため、完了時間だけで画像処理の速さを比較しない。最初の出力までの時間と全文は JSON に残した。

### 出力を画像と照合した所見

| ケース | Gemma 4 E2B | SmolVLM2 500M |
| --- | --- | --- |
| 画像なし | `NO_IMAGE` を返した | 画像内容を示唆する余計な文章を返した後、`NO_IMAGE.` と回答。厳密な指示には不一致 |
| 赤い円 | 赤い円・背景・文字なしを説明 | 赤い円を説明。一方で「色が付いていない」という矛盾と、依頼していない安全性への言及があった |
| 青い棒3本 | 棒グラフと説明したが **4本** と誤認 | **文書・文字のブロック** と誤認し、長い説明が出力上限で途切れた |
| 英語の荷札 | 茶色・白い領域は説明。レイアウトの説明が長く、文字は `DELIVERY` の後で出力が途切れた | 荷札の英語文字列を返した。荷物とラベルの関係の説明は不足 |

両モデルとも画像入力が成立したことと、内容が正確であることは分けて扱う。少数の合成画像で精度の優劣を確定しない。
現時点で Gemma 4 の出力をそのまま自動加工の根拠にはしない。

初回の全文・環境・メモリサンプル: [Gemma 4](evaluation-evidence/2026-10-20-vlm/gemma4-initial/result.json)、[SmolVLM2](evaluation-evidence/2026-10-20-vlm/smolvlm2-initial/result.json)。

## 日本語 OCR 結果を補足する比較

文字の読み取りは PaddleOCR に担当させる想定なので、VLM 自体の日本語 OCR 能力は必須条件にしない。
画像のみの説明に加え、日本語の架空荷札へ固定の文字列・位置・ブロック ID を与え、写真と関連付けられるかを確認する。

この補足データは **画像を描画した正解文字列であり、PaddleOCR を実行して得た結果ではない**。
OCR 自体の誤読・読み落としを含む結合精度や、リスク判定の精度は別に検証する。
質問・回答は英語でもよいが、補足データの日本語は翻訳せずに渡す。

### 質問の影響を分ける

最初の質問は物体・色・文字を説明してからブロックとの関係を答える形式だった。Gemma 4 で2回実行したところ、文字列と ID を返すところで両方とも途中で切れ、対応付けの評価に十分な回答を得られなかった。
その結果も [全文](evaluation-evidence/2026-10-20-vlm/gemma4-ocr-long/result.json) に保存した。

追加では「物体は英語12語以内、各ブロックの意味は英語3語以内、文字列を繰り返さない」という質問で両モデルを比較する。画像自体と日本語 OCR データは共通にする。
これはプロンプトも変更した追加実験なので、先の長い質問で得た数値と混ぜて平均しない。

### 短い質問で得た結果

両モデルで同じ APK・画像・固定 OCR 文字列・質問を使用。画像なし1件、日本語画像のみ1件、画像 + OCR 補足1件を実行した。

| 項目 | Gemma 4 E2B | SmolVLM2 500M |
| --- | --- | --- |
| 日本語画像のみ | 宛名・住所を一部読めたが、説明が長く途中で切れた | 画像にない文字を繰り返し生成し、内容を説明できなかった |
| 日本語画像 + OCR 補足 | 配送の住所・連絡先という文脈と、Recipient / Location / Phone number の対応を返した | 「政府と地方政府の代表者の会議」と説明。ブロック ID も返さず、内容と一致しなかった |
| OCR 補足時の最初の出力 | 22.836 秒 | 6.295 秒 |
| OCR 補足時の出力完了 | 28.535 秒 | 7.194 秒 |

Gemma 4 の実際の回答:

```text
Japanese address and contact information for delivery.
b1: Address
b2: Recipient
b3: Location
b4: Phone number
```

`b1` は住所そのものではなく「お届け先」という見出し、`b3` は実際には住所なので、厳密な分類では改善が必要。
それでも、文字を OCR から渡して意味を解釈する構成は、この1例では Gemma 4 で成立した。
SmolVLM2 にはこの日本語 OCR ケースで十分な解釈が得られなかった。少数のケースなので、モデル全般の精度を示す評価とはしない。

**Gemma 4 を引き続き主候補とし、次に Android 実機で測定する。** 小さいモデルへの置き換えは、この結果だけでは進めない。

短い質問の全文・環境・出力: [Gemma 4](evaluation-evidence/2026-10-20-vlm/gemma4-ocr-short/result.json)、[SmolVLM2](evaluation-evidence/2026-10-20-vlm/smolvlm2-ocr-short/result.json)。
機内モード・Wi-Fi 無効の記録: [offline-state.json](evaluation-evidence/2026-10-20-vlm/offline-state.json)。

今回の総実行数は25ケース（初回4件 × 2モデル、長い質問での再実行11件、短い質問での比較3件 × 2モデル）。
API の実行は全ケース完了したが、意味の照合では上記の誤り・途中切れを記録している。



## 容量で分かったこと

Gemma 4 は 2.59 GB のモデルに加え、この CPU 構成で約 963 MiB の XNNPACK キャッシュを生成した。
SmolVLM2 は約 291 MiB。容量はビルドやバックエンドにより変わる。
両モデルを置いた約 5.8 GB のエミュレーター領域では APK 更新時に空き容量不足になった。
評価アプリ専用領域の使っていないモデルと再生成可能なキャッシュを削除して継続した。
製品ではダウンロード前にモデル・キャッシュ・更新時の余裕を含めて確認し、未使用モデルを削除できるようにする。
