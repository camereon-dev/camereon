# 文字の個人情報を見分ける案（未着手）

2026-11-10 時点の検討メモ。実装・測定はまだしていない。採用時は Issue にして進める。

## 現状

文字検出（PP-OCRv5 mobile の検出モデルだけを同梱）は「文字が書いてある場所」を見つけるだけで、内容は読まない。看板・メニュー・名札をすべて同じ「文字」の候補として出し、隠すかどうかはユーザーが決める。

2026-11-01 に追加した ML Kit OCR の位置補助は、公開写真 18 枚のうち 16 枚で候補を増やさず撤去した（[評価記録](evaluation-evidence/2026-11-02-real-world/README.md)）。これは場所を探す補助としての評価で、内容を読んで判別する用途は試していない。

## 方針

端末内で文字を読み、内容から個人情報らしさを判定する。判定結果は候補の表示・初期選択に使い、最終判断はユーザーに残す。

1. **読み取り**: PaddleOCR の認識モデルを追加する。今の検出結果（傾きに沿った輪郭）から行ごとに画像を切り出して読むので、読んだ文字列と画面の枠が 1 対 1 で対応する。実行環境は同梱済みの ONNX Runtime をそのまま使える。
2. **形で判定する**: 電話番号・郵便番号・メールアドレス・URL・車のナンバー・カード番号らしいものを、正規表現や Google ML Kit の Entity Extraction（端末内・オフライン）で判定する。
3. **登録した言葉と照合する**: 自分の名前・住所の一部・学校名・会社名など、ユーザーが事前に登録した言葉と照らし合わせる。人名は形から判別しにくいため、これで補う。

## 読み取りモデルの候補

| モデル | サイズ | 根拠 |
| --- | ---: | --- |
| PP-OCRv6 small 認識 | 約 20MB | [以前の検証](ocr-evaluation.md)で、架空の名札・宛名・小さな書類の日本語をすべて正しく読めた |
| PP-OCRv5 mobile 認識 | 16.5MB（ONNX） | 公式に日本語対応（[配布ページ](https://huggingface.co/PaddlePaddle/PP-OCRv5_mobile_rec_onnx)の日本語の精度 0.758）。以前の検証では宛名の「〒」を「=」と誤認 |

- PP-OCRv6 tiny の認識は辞書にひらがな・カタカナがなく、日本語を読めない。
- 第一候補は v6 small。今の検出モデル（v5 mobile）の切り出しと組み合わせて精度・速度が保てるかを先に測る。
- APK は認識モデルの分だけ増える（16〜20MB 程度）。処理時間は行の数に比例するので、文字が 100 行以上ある写真での時間を測ってから採否を決める。

## 登録した言葉の照合

- 照合前に表記をそろえる。全角・半角を統一し（NFKC）、カタカナをひらがなにそろえ、空白を除き、英字の大文字・小文字を区別しない。
- 3 文字以上の言葉は、1 文字までの読み間違いを許容する。1〜2 文字の言葉は誤一致が多いので、完全一致に限るか登録時に警告する。
- 「担当 山田太郎 様」のように行の一部だけが一致した場合、認識モデルが出す文字ごとのおおよその位置から、その部分だけを隠せる見込み。精度は試作で確かめる。
- 登録した言葉そのものが個人情報なので、端末内だけに暗号化して保存する（Android は Keystore、iOS は Keychain）。外部への送信・ログ出力はしない。

## 画面での扱い

- 登録した言葉に一致した枠は、最初から「隠す」状態にし、登録した言葉による選択と分かる表示を付ける。タップで戻せる。
- 電話番号などの形の判定は、色を変えて目立たせるだけにし、隠すかどうかはユーザーが選ぶ。誤判定で看板まで隠したり、見逃しを「安全」と思わせたりしないため。
- 読み取った文字列はネイティブ側の処理の中だけで使い、Dart には「登録した言葉」「電話番号らしい」などの判定結果と枠だけを返す。文字列を画面・ログ・保存に出さない。
- 一致しなかったことは安全を意味しない。保存前の確認画面は残す。

## 進め方

1. 認識モデル（v6 small・v5 mobile）を追加し、公開写真 18 枚（[評価セット](evaluation-evidence/2026-11-02-real-world/sources.json)）で読み取り精度と処理時間を測る。
2. 形の判定と登録した言葉の照合を追加し、一致した枠の初期選択・強調表示を試作する。
3. 登録した言葉の設定画面と暗号化保存を追加する。
