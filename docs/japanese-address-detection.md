# 日本住所と顔を隠す編集フロー

通常の `CapturedPhotoScreen` は住所と顔を扱う。日本語OCRと既存のML Kit顔検出を実行し、住所候補・顔候補を初期選択する。一般文字・物体の検出器は起動しない。従来の検出器の比較テストだけが `includeOtherCandidates: true` を明示する。

字・大字・小字の単独表記（「字北山」「大字上野」「小字中原」）や番地付きの表記も住所候補にする。住所と顔は独立して解除・再適用できる。通常画面ではOCRと顔検出が完了するまで写真の表示と保存前確認を待つ。顔の再試行に対応し、新たに見つかった顔は過去の操作を取り消しても意図せず解除されない。

今回の字住所・顔の変更は単体・画面テストで検証。下記の端末検証記録は変更前の住所検出の記録であり、今回の変更の端末動作確認とは区別する。

## 入出力と処理

- 正規化済み画像を長辺2560px以内のRGBAに縮小し、`dev.camereon/japanese_ocr` に送る。
- Android: 同梱 `com.google.mlkit:text-recognition-japanese:16.0.1`。行ごとの文字と実測矩形を返す。推論・画素変換はワーカースレッドで行う。
- iOS: Vision `VNRecognizeTextRequest` の accurate / ja-JP。座標を左上原点へ変換し、行ごとの文字と矩形を返す。既存の直列ワーカーを使う。
- Dart側で文字数・型・座標を検証し、全角英数字とハイフンを正規化する。都道府県、市区町村、町域、数字・漢数字の丁目番地を住所候補にする。都道府県省略、北海道の条・方向表記、一部の建物名・部屋番号にも対応する。
- 都道府県・市区町村・番地の単独表記も候補にする。都道府県は47都道府県名で一致判定し、市区町村・町域・字名は同梱の公式データ由来辞書でも判定する。番地は「123番地」「一丁目二番三号」「1-2-3」などを扱い、数字だけの場合は「番地」「地番」のラベルを必要とする。電話番号・郵便番号・西暦のハイフン日付は単独番地として扱わない。連続した住所も都道府県・市区町村・町域・字・番地・後続文字に分割する。例えば「愛知県豊橋市大岩町字北山1-2-3ABC棟」は「愛知県」「豊橋市」「大岩町」「字北山」「1-2-3」「ABC棟」の6候補。番地直後の文字は既知の建物名接尾辞がなくても対象にするが、改行・OCR上の間隔・別項目ラベル（電話、氏名など）で止める。要素を覆う住所全体の枠は重ねない。
- 隣接する折り返しは行ごとの矩形に分け、行間をまとめて隠さない。離れた行や別段組は結合しない。
- 住所候補だけを元画像座標へ戻す。電話番号・郵便番号だけの行は住所候補にしない。氏名・一般文中も辞書と一致した地名部分は候補になる。顔は専用検出器で扱う。文字列・元画像をログへ出力せず、OCR文字列は永続保存しない。

最初のOCRと顔検出の完了までは写真の表示と保存前確認を待つ。候補は初期選択し、マスクテクスチャ生成前も不透明な塗りで覆う。タップ・一括切替・取り消し・確認画面からの戻りは選択状態だけを更新し、保存用JPEGはその選択から生成する。再検出で同じ範囲、または大きく重なる範囲が返っても解除済みの選択は戻さない。

## 判定範囲

デジタル庁のアドレス・ベース・レジストリ「町字マスター」全国データから作成した408,196語の辞書と表記ルールを併用する。都道府県、郡、市、区、町域・大字、小字を収録し、自治体名の末尾「市区町村郡」を除いた表記、町字の先頭「大字・小字・字」を除いた表記も検索する。「豊橋」「北山」は他に住所の手掛かりがなくても検出する。1文字の地名・省略表記は漢字のみ収録し、カタカナ・ひらがな・英数字などは除外する。地名と同じ人名・一般語を隠す場合がある。所在地全体の実在性や、現在の行政区分を保証する辞書ではない。

辞書未収録名、数字だけで番地と判断できない表記、別行・離れた欄の建物名、縦書き、小さい文字、傾き・ぼけ、OCR誤読は見落としの原因になる。辞書読み込みに失敗した場合は検出失敗として再試行を案内する。生成手順・出典・更新条件は[辞書README](../tools/address-dictionary/README.md)を参照。

iOS accurate認識の部分文字列矩形は単語単位になる場合があり、文字単位の厳密な切り抜きではない。隣接文字や傾いた行に対する矩形の精度を含め、一般写真の網羅的精度は未評価。保存前確認を残す。

## 検証

- 単体テスト: 単独の都道府県・市区町村・番地、同じ行の離れた要素、数字だけのラベル有無、都道府県あり・なし、全角数字、漢数字、ハイフン、北海道、京都、建物名・号室、折り返し、非住所の除外、OCR応答の検証。
- 画面テスト: 単独要素それぞれの解除・再適用と選択どおりの保存、住所・顔の初期非表示、一般文字・物体の検出器が起動しないこと、解除・再適用・取り消し、OCR中の保存防止、再試行での選択維持、選択どおりの保存。
- Android `Pixel_10a` エミュレーター: `integration_test/japanese_address_device_test.dart` を通過。東京都庁と大阪市役所の公開住所を描いた合成画像を実ML Kitで認識し、住所候補だけが出ること、解除・再適用、写真ライブラリへの保存を検証。JPEGの画素比較で、選択住所が加工され、解除住所・氏名・電話番号が保持されることを確認した。実写写真の精度評価ではない。
- Android debug APK / iOS simulator build は成功。
- iOS統合テストの実行は既存Runnerのシミュレーター対応設定で起動前に停止。起動済みiPhone 18 ProがRunnerの対応プラットフォームとして認められず、実行結果は未確認。ビルド成功をiOSでの動作確認とは扱わない。

## 辞書の照合と分割

OCR正規化後の文字列を同梱辞書で検索する。各位置の最長一致を採用し、例えば「豊橋市」と「豊橋」の重複枠を作らない。辞書の境界を優先し、表記ルールで得られた番地・後続文字は未被覆の部分を残す。「愛知県豊橋市大岩町字北山1-2-3ABC棟」は6候補として独立操作できる。文脈や番地がなくても登録地名を検索するため、一般文中の地名も隠す。

検索は端末内で完結し、辞書は一度読み込んで再利用する。バイナリ構造の検証は別の処理で行い、画面操作を止めない。出典・加工内容・利用条件をアプリ内ライセンス画面に表示する。

辞書版は単体・画面テストで検証し、端末OCRの再実行は未実施。上記の端末検証記録は辞書導入前の結果。

## 撮影後の確認画面

カメラで撮影した場合は、住所・顔の検出と加工が完了してから確認画面を表示する。「写真に保存」でそのまま保存でき、「編集する」で各候補の解除・再適用へ進む。編集後は「保存前に確認」で選択を反映した画像を再作成する。検出失敗時はステータスから再試行し、加工失敗時は「確認画像を再作成」で再試行できる。写真選択・サンプルの入口は従来どおり編集画面を開く。
