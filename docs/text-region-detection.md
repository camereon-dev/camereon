# 文字がありそうな領域の検出（Issue #14）

画像を開くと文字候補を自動検出し、写真上の枠タップで黒塗り・解除する。小さい文字を拾うため、高解像度の分割検出を自動で追加する。ピンチで最大8倍まで表示を拡大して、細かい枠を選べる。現在は回転矩形の採点と、1536pxの概要＋約1.5倍に拡大した最大4×4の分割検出を使う。文字の内容は認識しない（2026-11-01に試した日本語OCRの位置補助は、公開18枚でほぼ追加がなく2026-11-02に外した）。[小さい文字の改善と測定](small-text-detection.md)を参照。

## 範囲と方式の比較

以下は2026-10-27に検出専用モデルを選んだ時点の比較・実装記録。2026-11-01の精度改善で回転矩形の採点と分割検出を加え、2026-11-02に分割数の削減とOCR補助の撤去を行った。初期の960px概要・水平矩形採点の記述は当時のもの。現行の処理は上記リンクに記載する。

文字の位置だけが対象。住所・人名の判定、認識文字列の取得・保存・ログ出力、リスク評価、プレビュー中の連続検出は実装しない。

| --- | --- | --- | --- | --- |

## 実装と座標

```text
正規化済みSourcePhoto（編集画面と同じ画像）
  → Flutter側で長辺最大2560pxのPNGへ制限
  → MethodChannel → Androidバックグラウンド処理
  → 全体1536pxの概要検出 + 64px以上重なる最大4×4の切り出しを約1.5倍（1024px）へ拡大して検出
  → BGR / 正規化 / 32の倍数の入力 → 同じ検出専用ONNXモデル
  → 確率マップ → 重複統合・細部の枠を優先 → 転送画像の座標
  → DartでSourcePhotoの画素座標に戻し、HideRegionで外側へ丸める
  → 共通候補UI → ユーザーの適用 → 既存の黒塗りJPEG生成・保存
```

- DB確率しきい値0.3、矩形内の平均スコア0.6。境界を少し広げる。OpenCVを増やさず軸平行矩形でunclipを近似するため、公式の輪郭・回転矩形による後処理と完全一致しない。
- 小さな文字は縮小で消える場合がある。回転文字も囲むが背景を広く含む場合がある。検出範囲は情報の重要度や安全性を示さない。
- 最大500候補。打ち切り時は画面で通知する。文字0件と検出失敗は別の表示。
- `RegionDetector` / `RegionCandidate` / `CandidateKind` を顔・文字で共有できる。顔検出本体はこの変更には含めない。既存mainには顔候補UIがなかったため、共通の枠・個別適用・全適用を追加した。
- 検出中も届いた候補を選べる。再試行で適用済み範囲を消さない。確認画面へ進んだ後や画面破棄後の遅い結果は破棄する。ネイティブ推論自体の強制中止はしない。
- JPEGの向きは既存FlutterPhotoProcessorで正規化してから検出。表示の余白・画面座標は検出へ渡さない。

## 同梱・再現性

`android/app/src/main/assets/text_detection/model.json` に公式配布元、固定リビジョン、容量、SHA-256を記録。モデルをAPKへ含め、初回利用時のモデル取得も不要。実行時にもモデルのSHA-256を検査する。ネットワークコードを検出器へ持ち込まない。

依存は `com.microsoft.onnxruntime:onnxruntime-android:1.24.3` に固定。認識用SDK、Gemmaの取得、Google Play開発者サービスへは依存しない。モデルのApache-2.0全文とONNX RuntimeのMIT全文を同じassetsに含める。releaseのJNI保持設定を `android/app/proguard-rules.pro` に追加。

## 2026-10-27の従来方式の測定方法・結果

以下は全体960px・最大200候補の従来方式の記録。比較用の `AndroidTextRegionDetector(detailed: false)` に相当し、現在の詳細検出の測定値ではない。

2026-10-27、Apple Silicon Mac、Flutter 3.47.7 / Dart 3.13.5、Android 17 API 37 / ARM64エミュレーター。Debugビルド、CPU、ONNX Runtime内部2スレッド。実機の速度・消費電力の測定ではない。

元画像の準備後から、縮小・転送・モデル検査/ロード・推論・座標復元を含む `detect` 全体を測る。各画像4回、初回と後続3回の中央値を分ける。推論だけの値と混同しない。7種類の独自合成画像を同じ条件で比較する。

正解枠と予測枠はIoU >= 0.3で一対一に対応付ける。TPは対応数、FPは余分な枠、FNは見落とし。precision=TP/(TP+FP)、recall=TP/(TP+FN)。少数の合成画像上の検出指標であり、実写全般の認識精度や情報漏えいの防止率ではない。

| 画像 | 検出モデル 中央値ms | エッジ方式 中央値ms | 検出 TP/FP/FN | エッジ TP/FP/FN |
| --- | ---: | ---: | --- | --- |
| 配送ラベル640px | 137.8 | 56.2 | 4/0/0 | 0/0/4 |
| 配送ラベル1280px | 291.7 | 116.1 | 4/0/0 | 0/0/4 |
| 90度回転 | 133.9 | 50.5 | 4/2/0 | 0/0/4 |
| 低コントラスト | 143.1 | 46.9 | 4/0/0 | 0/0/4 |
| 合成書類8行 | 143.5 | 50.3 | 8/0/0 | 8/0/0 |
| 無地 | 139.2 | 48.1 | 0/0/0 | 0/0/0 |
| 文字なし模様 | 134.2 | 46.2 | 0/0/0 | 0/26/0 |

7画像合計: 検出モデル precision 92.3%、recall 100%（TP24/FP2/FN0）。エッジ方式 precision 23.5%、recall 33.3%（TP8/FP26/FN16）。初回の検出モデル呼び出しは586.1ms、エッジ方式は70.0ms。端末の負荷やウォームアップで変動する。90度回転では背景2箇所を誤検出したため、候補の確認・個別適用を残す。

[測定JSON](evaluation-evidence/2026-10-27-text-regions/results.json)に画像ごとの初回・中央値・枠・TP/FP/FN・環境・オフライン条件を記録。Androidの機内モードON、Wi-Fi/データOFF、既定ネットワークなしを確認して実行し、終了後は元の通信設定へ復元した。

- 静的解析とunit/widget全104件: 成功。
- Androidの検出比較・UIからJPEG保存の結合2件: オンラインでもオフラインでも成功。
- 既存Android結合6件（カメラ起動、保存、不正入力拒否、サンプル編集、撮影メタデータ・向き）も成功。
- 1280px画像は長辺960pxへ縮小して検出し、元画像座標へ戻した4行すべてを照合。
- 保存JPEGは640×640、4行の中心画素が黒、EXIFなし、一時ファイル削除を確認。
- release APKを通常起動して、4行の候補と全適用による黒塗りも目視確認。

[release版の候補表示](evaluation-evidence/2026-10-27-text-regions/release-candidates.png) / [適用後](evaluation-evidence/2026-10-27-text-regions/release-applied.png)

同じソース起点・`flutter build apk --release --target-platform android-arm64`・同じ署名構成で比較。追加前61,468,120 bytes、追加後92,107,899 bytes、**増分30,639,779 bytes（約30.6MB）**。モデルだけでなくONNX Runtimeのネイティブライブラリも増えるため、モデル容量をAPK差分として扱わない。独立した検出器を優先した代わりにAPKは増える。容量を優先する場合は選択演算子だけのランタイムビルドを別途評価する。本体に比較用エッジ方式は含めない。release APK内のモデルSHA-256・ライセンス同梱・ARM64のみであることも確認した。

## 確認手順

1. 起動画面の「サンプルで試す」を開く。
2. 自動検出で配送ラベルの4行に枠が出ることを確認。
3. 枠をタップして黒塗りし、取り消しで戻せることを確認。必要ならピンチで拡大する。
4. 矢印から保存前確認→写真に保存。JPEGの解像度・黒塗り位置・EXIF除去を確認。
5. 端末の通信を切った状態でも同じ手順を実施。

### 番号ボタンの切替（2026-10-27）

1→黒塗り、再び1→元の写真を表示。1〜4の番号・並び・位置は維持する。
ボタンの選択状態と重ねた枠の色を同期する。保存前確認には現在選択中の候補と手動範囲だけを渡す。
unit/widget全104件で、独立したON/OFF、ボタン位置、保存前確認への反映、手動範囲との重なりを検証した。
Android結合テストでも全選択から1だけ解除し、保存JPEGで1の領域を再表示・他3行を黒塗りのまま保持することを確認。release通常起動でも[1を選択](evaluation-evidence/2026-10-27-text-regions/release-toggle-selected.png)→[1を解除](evaluation-evidence/2026-10-27-text-regions/release-toggle-deselected.png)を確認した。

再実行コマンドは[評価ツールのREADME](../tools/text-region-eval/README.md)を参照。通常の静的解析・widget testに加え、Androidの新しい結合テストを実施する。

## 残る制約

実機、実写の住所・名札・書類、手書き、小さい/ぼけた/斜めの文字、夜間、縦書き、前面カメラの鏡像、長時間の発熱・ピークメモリは未評価。誤検出・見落としがあるため、手動の確認・編集を残す。今回の課題で文字内容の精査や顔検出の完了を扱わない。
