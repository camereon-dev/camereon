# 顔・人物・画面・文字検出の統合

通常の撮影・写真選択から同じ編集画面へ入り、Gemmaを準備せずに利用できる。正規化画像の読込後に全検出器を自動で開始し、検出した枠を画像上で選択する。

## 共通点と役割

| 項目 | 顔 | 人物・画面 | 文字 |
| --- | --- | --- | --- |
| 推論 | 同梱ML Kit、ACCURATE | 同梱YOLO26s、ONNX Runtime | 同梱PP-OCRv5、ONNX Runtime |
| 範囲 | 顔の周囲に各辺10%の余白 | 人物全体、モニター・PC・スマホ全体 | 文字の位置。内容認識は行わない |
| 入力 | 向きを正規化した同じSourcePhoto | 同左 | 同左 |
| 座標 | 最大長辺1600pxから元画像へ復元 | 最大長辺1600pxから640/1280pxの2解像度、元画像へ復元 | 最大長辺960pxから元画像へ復元 |
| 編集への受渡し | 顔IDに対応するRegionCandidateへ変換 | RegionCandidateのHideRegion | 同左 |
| 開始 | 画像読込後に自動 | 同左 | 同左 |
| 操作 | 画像上の枠をタップして適用・解除 | 同左 | 同左 |

共通の契約は「同じ正規化画像を使い、元画像の画素座標のHideRegionを返す」こと。検出器ごとの前処理や検出設定を同一にする必要はない。

## 写真を主役にした編集UI

- 写真と、その色をぼかした背景を表示し、上にステータス、下に小さなガラス調バーを重ねる。ぼかし・半透明のグラデーション・細いハイライトでガラスの質感を表現する。OS固有のLiquid Glass APIへの依存はない。
- 写真・背景のぼかし・候補枠・スキャンは描画を分離する。編集画面へ入る前にライブカメラを解放し、戻ったときに再開する。
- 検出が動いている間だけ、光のシートが写真の上を走る。結果が返ると候補の輪郭がフェードして現れる。端末のアニメーションを減らす設定ではスキャンの移動と枠の登場アニメーションを停止する。推論完了を待つための演出用遅延は加えない。
- 手動ドラッグによる範囲追加、番号一覧、常設の検出開始・一括適用・リセットボタンは廃止。枠タップで黒塗りし、再タップで解除する。ドラッグでは範囲を追加しない。
- バーは「すべて／顔だけ」、取り消し、保存前確認の矢印のみ。保存前確認では枠とスキャンを外したJPEGを大きく表示し、「写真に保存」で保存する。加工・保存の失敗時も選択を保持する。
- 「顔だけ」は候補表示の切替。検出処理は初期表示ですべて実行し、表示を切り替えても既存の黒塗りは保持する。
- 枠から8論理ピクセル以内も選択対象とする。重なる枠は近い枠辺と小さい候補を優先する。完全に同じ範囲の候補はタップ時だけ選択メニューを出し、顔・人物・文字などを選び分ける。
- 各枠には種類と選択状態のSemanticsを付け、スクリーンリーダーからも個別に操作できる。枠の色は座標ではなく候補の選択状態で決めるため、同位置の別種類まで選択済みの色に変えない。

## 非同期処理と保存

顔検出とは別に、ONNXの文字→人物・画面を直列に実行し、モデル同時実行のピークメモリを抑える。1種類の失敗でも他の検出を続ける。失敗した場合は上のステータスをタップして再試行できる。顔の重複を含む既知の精度制約は、UI変更で解決済みとはしない。

選択と取り消しの履歴を全種類で共有する。候補そのものを選択対象として保持し、同じ幾何形状の別候補も独立して選択・解除できる。同じ範囲は保存時に一度だけ加工する。再検出で同じ種類・範囲が返れば既存の候補を再利用し、選択中や履歴に残る候補も操作可能な状態で保持する。

保存前確認時のスナップショットだけを加工・保存し、遅れて届く候補で確認画像を変更しない。確認に進んだ後や画面を閉じた後に、待機中の次の自動検出を開始しない。画面破棄後のネイティブ応答も返さない。

## 検証

UIテストは、全検出器の自動開始・順次実行、失敗後の再試行、枠タップ・解除・全種類の取り消し、同位置候補の独立操作、顔だけ表示、ドラッグ無効化、保存中の状態保持、狭い画面と拡大文字を確認する。手動ドラッグ・番号ボタンを前提としていた旧テストは現在の操作へ更新する。

Androidのテストは1ファイルずつ直列実行する。合成の送り状で実PP-OCRv5の枠選択からJPEG保存、公開の評価用画像で実ML Kitの顔枠タップ・取り消し・MediaStore読戻し、既存の実写3枚で人物・画面検出と枠選択からの保存を確認する。元画像・defines・実写スクリーンショットはGit管理外とし、評価fixtureを埋め込んだテストAPKは配布用APKと分ける。

2026-10-28のUI更新では、整形・静的解析・全126テストが成功。Android 12 ARM64エミュレーターで、文字検出2件・顔検出1件・画像の向きと保存3件・人物と画面検出2件の計8テストが成功した。今回のUI変更の実機検証は未実施。[画面デモ](evaluation-evidence/2026-10-28-glass-editor/editor.gif)はプロジェクト内の合成サンプルを使い、エミュレーターを縦画面にして通常のDebug APKを録画したもの。

## 人物の手前にあるPCを残す場合

現在の人物候補は長方形なので、その内側に写るPCも黒塗りになる。PCの検出枠を人物の矩形から差し引くと、枠に含まれる人物の手や腕まで露出させる可能性があるため採用しない。

輪郭に沿って人物の可視部分だけを塗るには、[インスタンスセグメンテーション](https://docs.ultralytics.com/tasks/segment/)が返す物体ごとの画素マスクが必要になる。現行のYOLO26s検出モデルとHideRegionの矩形保存契約だけでは実現できず、本変更には含めない。追加する場合はモデル・ネイティブ出力・プレビュー・JPEG書出しを一貫してマスクへ対応させ、人物とPCが重なる実写で境界の塗り残しと端末性能を検証する。

モデルの出力を統計的なリスク値として合算せず、候補0件を「安全」と判定しない。精度評価は[顔検出](face-detection.md)と[実写の検出比較](detector-evaluation.md)を参照。
