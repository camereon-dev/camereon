# 顔・人物・画面・文字検出の統合

PR #38のML Kit顔検出を、mainに入ったPR #39のYOLO人物・画面検出と組み合わせる。通常の撮影・写真選択から同じ編集画面へ入り、Gemmaを準備せずに利用できる。

## 共通点と役割

| 項目 | 顔（#38） | 人物・画面（#39） | 文字（#14） |
| --- | --- | --- | --- |
| 推論 | 同梱ML Kit、ACCURATE | 同梱YOLO26s、ONNX Runtime | 同梱PP-OCRv5、ONNX Runtime |
| 見つける範囲 | 顔の周囲に各辺10%の余白 | 人物全体、モニター・PC・スマホ全体 | 文字の位置。内容認識は行わない |
| 入力 | 向きを正規化した同じSourcePhoto | 同左 | 同左 |
| 検出座標 | 最大長辺1600pxから元画像へ復元 | 最大長辺1600pxから640/1280pxの2解像度、元画像へ復元 | 最大長辺960pxから元画像へ復元 |
| 編集へ渡す型 | FaceCandidateのHideRegion | RegionCandidateのHideRegion | 同左 |
| 開始 | 画像読込後に自動、失敗・中止時に再試行 | 画像読込後に自動、必要なら再検出 | 同左 |
| 適用 | 画像上の枠タップ・個別ボタン・一括適用、顔IDで履歴管理 | 枠タップ・番号ごとの選択・解除、一括適用 | 同左 |

共通の契約は「同じ正規化画像を使い、元画像の画素座標のHideRegionを返す」こと。検出器ごとの前処理や検出設定を同一にする必要はない。

## 結合した処理

- 画像の読込・向きの正規化、手動選択、保存前確認、JPEG生成、MediaStore保存を共有する。
- 候補枠は共通の `CandidatePainter` で描く。顔の既存の適用操作・履歴を維持しながら、描画時に `CandidateKind.face` へ変換する。
- 顔枠は「顔1」、人物・画面・文字の枠は従来の番号を使う。別系列の候補がどちらも「1」とだけ表示される混同を防ぐ。
- 黒塗りは手動・適用済み顔・選択済み人物/画面/文字の範囲を合成する。同じ幾何形状は一度だけ加工するが、選択状態は別に保持する。顔の解除で同位置の文字・人物や手動領域を消さない。
- 人物と文字の選択も座標だけでは共有しない。候補そのものを選択対象として保持し、再検出で同じ種類・範囲が返れば既存の候補を再利用する。同位置の人物が選択済みでも、文字候補は自動選択されない。これを選択ボタンの状態と保存範囲の両方で回帰テストする。
- 「取り消す」は顔・手動の履歴を戻す。人物・画面・文字は番号で解除する。「すべてリセット」は両方の状態を解除する。
- 保存前確認時のスナップショットだけを加工・保存し、後から届く候補で確認画像を変更しない。画面破棄後のML Kitネイティブ応答も返さない。
- 既存の写真選択、Debug/Releaseビルド、VS Codeデバッグ設定、バージョン表示を保持する。顔のために通常フローへGemmaの入口を戻さない。

顔の非同期制御・取り消し履歴と、他の検出器の選択制御は、それぞれ既存の仕組みを利用する。

## 自動検出と画像上の操作

正規化画像の読込後に全検出器を自動で開始する。顔検出とは別に、ONNXの文字→人物・画面を直列に実行し、モデル同時実行のピークメモリを抑える。どれかが失敗しても他の種類の検出は続け、それぞれの結果・エラーを表示する。検出中も手動編集と保存前確認を使える。確認に進んだ後や画面を閉じた後に次の自動検出を開始せず、遅れて届く結果を保存画像に混ぜない。

候補の枠内をタップすると即座に黒塗りし、同じ場所をもう一度タップすると解除する。枠から8論理ピクセル以内も選択対象にする。重なる候補は近い枠辺を優先し、それ以外では面積の小さい候補を優先するため、人物内の顔やPCを個別に操作できる。完全に同じ範囲の候補は顔→その他の表示順を維持し、各番号ボタンでも個別に切り替えられる。指の微小な動きはタップとして扱い、18論理ピクセルを超えるドラッグは従来の手動範囲追加にする。

「顔だけ」は候補表示の切替。顔検出はYOLO人物検出とは独立しており、この表示では人物・画面・文字の枠や番号を隠し、「顔をすべて適用」で顔の範囲だけを一括適用できる。表示切替で既存の手動範囲や他の種類の黒塗りを消さず、保存対象にも残す。検出処理自体は初期表示ですべて実行する。

## 人物の手前にあるPCを残す場合

現在の人物候補は長方形なので、その内側に写るPCも黒塗りになる。PCの検出枠を人物の矩形から差し引く方法では、枠に含まれる人物の手や腕まで露出させる可能性があるため採用しない。

輪郭に沿って人物の可視部分だけを塗るには、[インスタンスセグメンテーション](https://docs.ultralytics.com/tasks/segment/)が返す物体ごとの画素マスクが必要になる。現行のYOLO26s検出モデルとHideRegionの矩形保存契約だけでは実現できないため、本変更には含めない。追加する場合はモデル・ネイティブ出力・プレビュー・JPEG書出しを一貫してマスクへ対応させ、人物とPCが重なる実写で境界の塗り残しと端末性能を検証する。顔だけを隠せばよい写真では「顔だけ」の選択を使える。

## 確認すること

顔・人物・文字が同じ範囲を指すケースを追加し、1種類を解除しても他の適用と手動範囲が残ること、再検出で他の種類が消えないこと、共通描画でも「顔1」を表示することを自動テストする。

操作欄が長くなったため、画面テストではスクロールして操作対象を表示してから押す。エンジンの画像デコードは実時間で完了を待ち、固定の短い待ち時間だけに依存しない。

Androidの端末テストは1ファイルずつ直列実行する。公開の評価用画像を使った実ML Kitの候補適用・解除・保存先JPEG読戻しと、既存の人物・画面検出を確認する。評価用画像を埋め込んだテストAPKは配布用APKと分け、元画像・defines・実写スクリーンショットはGit管理外に置く。

2026-10-28の自動化変更では、`mise run check`（format・解析・全130テスト）が成功。Android 12 ARM64エミュレーターでも、文字の自動検出→画像の枠タップ→JPEG保存、実ML Kitの「顔だけ」表示→枠タップで適用・解除→顔一括適用→MediaStore読戻し、既存の実写3枚の人物・画面検出→自動候補の一括適用→保存が成功した。実写はテストAPKに埋め込まず、Debugアプリの専用領域へ一時配置して検証後に削除した。今回の自動化変更の実機検証は未実施。

## 残る制約

ML Kitで報告済みの重複候補、真横の横顔、実機固有の姿勢・鏡像、実機性能・発熱は、この統合で解決済みとはしない。YOLOも画面内の人物を検出するため、顔候補と対象が重なることがある。全候補を必ず隠す必要があるという意味ではなく、ユーザーが必要な範囲を選択する。

モデルの出力を統計的なリスク値として合算せず、候補0件を「安全」と判定しない。詳細な精度評価は[顔検出](face-detection.md)と[実写の検出比較](detector-evaluation.md)を参照。
