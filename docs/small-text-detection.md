# 小さい文字の検出を改善する

写真全体を960pxまで縮小すると、画面・書類などの細い文字が数画素になり、検出できなくなる。通常の自動検出を高解像度の分割処理へ変更し、同じ同梱PP-OCRv5 mobile検出モデルで細部を調べる。文字列を読むOCRやVLM、モデルの追加ダウンロードは加えない。

## 処理

1. 編集画面と同じ正規化画像を、長辺2560px以下のPNGへ制限して転送する。ネイティブ側の上限は32MiB。
2. 全体を長辺960px以下にして概要を検出する。転送画像が960px以下なら従来と同じ1回の検出で終える。
3. 大きい画像は `max(384, ceil(長辺 / 128) * 32)` pxの正方形で切り出し、隣と最低25%重ねる。各軸最大5枚、概要を含め最大26回。各切り出しを長辺960pxへ拡大し、32の倍数へ調整して推論する。
4. 切り出しの原点を戻して重複を統合する。同じ文字列の横幅を捉えた細部の枠があれば、縮小由来の過大な概要枠より優先する。大きな既知の文字の部分ストロークは追加候補にせず、平坦な境界線と孤立した正方形の模様も細部の候補から抑制する。
5. 元画像の座標へ復元し、従来と同じ選択・黒塗り・保存へ渡す。最大500候補、打ち切り時は既存の通知を使う。

画像・テンソルは1枚ずつ解放し、1リクエスト内の全推論で同じセッションを使う。モデル確率0.3・矩形平均0.6は維持する。細部だけに形状と色変動の条件を加え、通常の概要検出は維持する。色変動はRGB各チャンネルで判定し、輝度差だけでは見えにくい色付き文字も対象とする。

入力寸法と検出結果の関係は[PaddleOCRの検出モジュール仕様](https://paddlepaddle.github.io/PaddleOCR/v3.1.0/en/version3.x/module_usage/text_detection.html)を参照。分割・統合・候補上限は本アプリ独自の実装。

## 選択

写真をピンチで最大8倍まで表示拡大し、移動して細かい枠を選べる。常設の操作ボタンは増やさない。実際に触れた枠を、その近くにある小さな枠より優先する。近くをタップした場合は距離で判断し、許容幅は拡大率を含めて8論理ピクセルに保つ。

表示の拡大は検出結果や保存解像度を変えない。タップを写真の元座標へ戻し、保存前確認・JPEG生成には同じHideRegionを渡す。ドラッグで手動の黒塗り領域は追加しない。

## Androidでの比較

2026-11-01、Android 12 API 31 ARM64エミュレーター、Debug、CPU、ONNX Runtime内部2スレッド。各画像・方式1回の壁時計値で、転送・セッション作成を含み、SourcePhotoの読込・正規化は除く。速度の中央値や実機性能の測定ではない。

実際のAndroid日本語フォントを明示して描いた架空の文字列20行と正解枠を使う。テスト用の四角い代替フォントには依存しない。IoU ≥ 0.3で一対一照合し、TP/FP/FNを記録する。

| 合成画像 | 従来 TP/FP/FN | 詳細 TP/FP/FN | 従来→詳細 ms |
| --- | --- | --- | ---: |
| fontSize 6、2560×1440 | 0/0/20 | 20/0/0 | 529→2786 |
| 同等の文字、3840×2160から座標復元 | 0/0/20 | 20/0/0 | 174→2579 |
| fontSize 8、2560×1440 | 14/6/6 | 20/0/0 | 164→2548 |
| fontSize 14、2560×1440 | 20/0/0 | 20/0/0 | 164→2532 |
| 無地2560×1440 | 0/0/0 | 0/0/0 | 157→4100 |

fontSize 8の従来方式では、位置は近いが枠が大きすぎて照合条件を満たさない結果が含まれる。細部の枠を優先することで改善した。切り出しをまたぐ文字と、拡大した配送ラベル1280pxの4行が重複せず残ることも確認する。

ユーザー提供の実写3枚も同一の正規化画像で比較した。候補数は2→7、9→100、0→18。モニターや遠くの書類の追加候補を目視確認したが、模様などの誤候補も残る。実写には網羅的な正解ラベルがないため、候補数を精度率や漏えい防止率として扱わない。画像・枠付き実写はGitへ載せず、公開記録は候補数と時間だけにする。

整形・静的解析・全131テストと、Android上の小文字比較・実写比較・従来比較・拡大後の枠選択からJPEG保存を確認した。[測定JSON](evaluation-evidence/2026-11-01-small-text/summary.json)に記録。精度優先のため大きい画像では処理時間が増える。極端に潰れた文字、一文字、斜めの文字、模様との判別には制約があり、全写真での100%検出を示す結果ではない。この変更の実機性能・発熱は未確認。

## 再現

```sh
mise run check
CAMEREON_DETECTOR_PREVIEW=1 mise run small-text-test -- -d emulator-5554
CAMEREON_DETECTOR_PREVIEW=1 mise exec -- flutter test integration_test/text_regions_device_test.dart -d emulator-5554
mise run detector-debug-install -- emulator-5554
```

検証用フォントは `/system/fonts/NotoSansCJK-Regular.ttc` を使う。端末で場所が異なる場合は `--dart-define=SMALL_TEXT_FONT_PATH=...` を指定する。フォントや評価fixtureを通常のAPKへ追加しない。

実写比較は `--dart-define=RUN_PRIVATE_SMALL_TEXT_TESTS=true` で起動し、テストAPKの導入後に `tools/detector-eval/stage_android.py` で同意済み3画像を配置する。テスト後に元画像を端末内の専用領域から削除する。測定ログにも認識文字列や画像のバイト列を出さない。

PC上の再現は `tools/detector-eval/requirements-small-text.txt` を使い、`tools/detector-eval/small_text.py` にローカル画像と `.private/` 以下の出力先を指定する。比較中のPythonソケット接続を拒否する。補間・ランタイムがAndroidと異なるため、PCの結果を端末の速度や完全に同じ検出結果とはみなさない。
