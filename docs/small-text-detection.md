# 小さい文字の検出を改善する

写真全体を960pxまで縮小すると、画面・書類などの細い文字が数画素になり、検出できなくなる。通常の自動検出を高解像度の分割処理へ変更し、同じ同梱PP-OCRv5 mobile検出モデルで細部を調べる。さらに傾きに沿った採点を使う。操作は増やさず、自動で実行する。

## 処理

1. 編集画面と同じ正規化画像を、長辺2560px以下のRGBA画素のままネイティブへ渡す（PNG符号化を挟まない。2560pxのPNG符号化はエミュレーターで0.8〜0.95秒、生画素は約60ms）。ネイティブ側は `幅×高さ×4` バイトと寸法上限を検査する。
2. 全体を長辺1536px以下にして、文字列全体の文脈を保つ概要検出を行う。転送画像が960px以下なら分割を省く。比較用の `detailed: false` は旧来の960px・水平矩形採点を保持する。
3. 大きい画像は各軸で「1辺704px以下・隣と64px以上重なる最小枚数」に分割する（`TextRegionDetector.plan`）。2560pxなら688pxが4枚、1920pxなら683pxが3枚、1024pxなら2枚。各切り出しを長辺1024pxへ約1.5倍に拡大して推論する。最大4×4枚、概要を含め最大17回。2026-11-01の方式（384〜640pxを960pxへ、25%重複、最大26回）より2560×1920で20→12枚、1308×1780で20→6枚に減る。
4. 確率成分の凸包から最小面積の回転矩形を求め、その内側だけでスコアを採点する。斜め文字の外側の背景を混ぜない。矩形内の文字の穴・文字間は採点対象のままで、しきい値を超えた画素だけの平均にはしない。細部のほぼ正方形の成分は一律に捨てず、スコア0.75以上なら一文字の候補として残す。平坦な縁の除外は維持する。
5. 切り出しの原点を戻して重複を統合する。同じ文字列の横幅を捉えた細部の枠があれば、縮小由来の過大な概要枠より優先する。大きな既知の文字の部分ストロークは追加候補にしない。縦横とも8px未満の点は候補にしない。
6. 各成分の凸包を同じ余白ぶん外側へ広げた多角形も返す（統合時は両者の凸包）。斜めの文字は外接矩形ではなくこの輪郭で隠すので、傾いた行の周りの背景まで塗らない。元画像の座標へ復元し、従来と同じ選択・保存へ渡す。最大500候補、打ち切り時は既存の通知を使う。
7. 編集画面では、顔候補の内側に収まる文字候補（目・眼鏡）と、顔の大部分を囲むだけの文字候補（スカーフの縁などの斜め成分）を表示しない。選択済みの候補は残し、顔と完全に一致する候補は従来どおり選択メニューで種類を選べる。

モデルはプロセス内で1つのONNXセッションを再利用する（`OnnxSessions`）。初回にSHA-256を検査し、各推論後にアリーナを縮小してピーク作業メモリを保持しない。メモリ不足の通知と画面破棄で解放する。推論スレッドはコア数−1を2〜4に収める（4コアのエミュレーターで2→4スレッドは1.2〜2.3倍。XNNPACK実行プロバイダーはCPUより遅かったため使わない）。ネイティブ側で `OutOfMemoryError` を含む `Throwable` を失敗として返し、アプリを落とさない。

2026-11-01に追加した同梱日本語ML Kit OCRの位置補助は、公開実写18枚のうち16枚で追加候補が0件（残り2枚で+3・+1）だったため2026-11-02に外した。APKの依存も削除した。画像は端末内で処理し、文字の内容は認識しない。

入力寸法と検出結果の関係は[PaddleOCRの検出モジュール仕様](https://paddlepaddle.github.io/PaddleOCR/v3.1.0/en/version3.x/module_usage/text_detection.html)を参照。分割・統合・候補上限は本アプリ独自の実装。

## 選択

写真をピンチで最大8倍まで表示拡大し、移動して細かい枠を選べる。常設の操作ボタンは増やさない。実際に触れた枠を、その近くにある小さな枠より優先する。近くをタップした場合は距離で判断し、許容幅は拡大率を含めて8論理ピクセルに保つ。

表示の拡大は検出結果や保存解像度を変えない。タップを写真の元座標へ戻し、保存前確認・JPEG生成には同じHideRegionを渡す。ドラッグで手動の黒塗り領域は追加しない。

## 分割検出を導入した時点のAndroid比較（2026-11-01、旧分割方式）

2026-11-01、Android 12 API 31 ARM64エミュレーター、Debug、CPU、ONNX Runtime内部2スレッド。各画像・方式1回の壁時計値で、転送・セッション作成を含み、SourcePhotoの読込・正規化は除く。速度の中央値や実機性能の測定ではない。

実際のAndroid日本語フォントを明示して描いた架空の文字列20行と正解枠を使う。テスト用の四角い代替フォントには依存しない。IoU ≥ 0.3で一対一照合し、TP/FP/FNを記録する。

| 合成画像 | 従来 TP/FP/FN | 詳細 TP/FP/FN | 従来→詳細 ms |
| --- | --- | --- | ---: |
| fontSize 6、2560×1440 | 0/0/20 | 20/0/0 | 529→2786 |
| 同等の文字、3840×2160から座標復元 | 0/0/20 | 20/0/0 | 174→2579 |
| fontSize 8、2560×1440 | 14/6/6 | 20/0/0 | 164→2548 |
| fontSize 14、2560×1440 | 20/0/0 | 20/0/0 | 164→2532 |
| 無地2560×1440 | 0/0/0 | 0/0/0 | 157→4100 |

fontSize 8の従来方式では、位置は近いが枠が大きすぎて照合条件を満たさない結果が含まれる。細部の枠を優先することで改善した。切り出しをまたぐ文字と、拡大した配送ラベル1280pxの4行が重複せず残ることも確認する。

ユーザー提供の実写3枚も同一の正規化画像で比較した。候補数は2→7、9→100、0→18。モニターや遠くの書類の追加候補を目視確認したが、模様などの誤候補も残る。実写には網羅的な正解ラベルがないため、候補数を精度率や漏えい防止率として扱わない。画像・枠付き実写はGitへ載せず、公開記録は候補数と時間だけにする。

整形・静的解析・全131テストと、Android上の小文字比較・実写比較・従来比較・拡大後の枠選択からJPEG保存を確認した。[測定JSON](evaluation-evidence/2026-11-01-small-text/summary.json)に記録。精度優先のため大きい画像では処理時間が増える。極端に潰れた文字、一文字、斜めの文字、模様との判別には制約があり、全写真での100%検出を示す結果ではない。この変更の実機性能・発熱は未確認。

## 2026-11-02 公開実写18枚での再評価と負荷対策

分割の削減・OCR撤去・生画素転送・セッション再利用の後、公開のWikimedia Commons写真18枚（博物館ラベル、図書館、飲食店、献立、駅名標、名札、駐車場、人混み）をAndroidエミュレーターで再評価した。詳細検出は1枚 99〜4264 ms（18枚合計 39192 ms。2026-11-01方式の同条件の合計は 181941 ms で、その前半はホスト負荷で遅い）、候補数は同程度。合成の極小文字20行はTP 20を維持。顔の最小サイズを0.02へ下げ、車両候補を追加し、顔と重なる文字候補を非表示にした。表・設定比較・メモリ・残る制約は[評価記録](evaluation-evidence/2026-11-02-real-world/README.md)を参照。実機の速度・発熱は未測定。

## 再現

```sh
mise run check
mise run text-geometry-test
CAMEREON_DETECTOR_PREVIEW=1 mise run small-text-test -- -d emulator-5554
CAMEREON_DETECTOR_PREVIEW=1 mise exec -- flutter test integration_test/text_regions_device_test.dart -d emulator-5554
CAMEREON_DETECTOR_PREVIEW=1 mise run public-photo-text-test -- -d emulator-5554
mise run detector-debug-install -- emulator-5554
```

検証用フォントは `/system/fonts/NotoSansCJK-Regular.ttc` を使う。端末で場所が異なる場合は `--dart-define=SMALL_TEXT_FONT_PATH=...` を指定する。フォントや評価fixtureを通常のAPKへ追加しない。

公開実写の評価は `integration_test/blackboard_text_device_test.dart` が任意の `sources.json`（id・SHA-256）を受け取る。テスト開始後に `tools/detector-eval/blackboards_android.py` で画像を配置し、結果JSON・黒塗りJPEGを回収する。設定比較は `integration_test/detector_probe_device_test.dart`（`--dart-define=RUN_DETECTOR_PROBE=true`、`--marker 'detector probe: timing' --ready PROBE_READY --collect probe.json`）を使う。測定ログにも認識文字列や画像のバイト列を出さない。

PC上の再現は `tools/detector-eval/requirements-small-text.txt` を使い、`tools/detector-eval/small_text.py` にローカル画像と `.private/` 以下の出力先を指定する。分割の計画と1024px拡大は端末と同じ式を使う。比較中のPythonソケット接続を拒否する。補間・ランタイムがAndroidと異なるため、PCの結果を端末の速度や完全に同じ検出結果とはみなさない。
