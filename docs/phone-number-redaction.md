# 電話番号などの数字列を隠す

日本語OCRの結果を住所・郵便番号・番号で共有する。Androidは同梱ML Kit、iOSはApple Visionを使い、候補の判定は共通のDartコードで行う。OCR文字列は端末のメモリ内で処理し、候補には座標と初期選択の情報だけを持たせる。

## 自動で隠す範囲

- 1つの数字列として読めた9桁以上の候補は、先頭番号やラベルを問わず既定で隠す。電話番号のほか、管理番号、カード形式の数字列、JANコード、桁数の長い日時も対象になり得る。
- `050`、`060`、`070`、`080`、`090` で始まる7〜8桁の数字列も既定で隠す。
- 全角の数字・記号、ハイフン、括弧、`+81` 付きの番号を扱う。数値らしい列の中の `O` と `o` は、補正後に自動選択の条件を満たす場合に `0` として扱う。
- 空白で分かれた数字は、同じ行の近い位置にある3桁以上のまとまりをつなぐ。`+81 3 0000 1234` や `03 0000 1234`、`06 0000 1234` では、短い先頭のまとまりもつなぐ。離れた欄や行はつながない。
- `TEL`、「電話番号」「連絡先」などの近くにある7〜8桁のローカル番号は、手動で選べる候補にする。日付と判定できる8桁の表記や、英数字・メールアドレスに埋め込まれた数字は対象外になる場合がある。
- 通常の郵便番号は住所候補として扱う。自動選択する番号の中に郵便番号のような形が含まれる場合や、住所と番号の枠がほぼ同じ場合は、番号の枠にまとめる。`TEL:123-4567` は手動選択できる番号候補になる。

## 編集と保存

設定の「番号」をオフにすると、候補は検出して枠で表示し、初期状態では選択しない。枠のタップ、「番号」の一括切り替え、ペンと消しゴム、取り消しとやり直しを使える。再検出で同種のほぼ同じ候補が返っても、解除済みの番号を自動で隠し直さない。

撮影・写真選択のどちらも編集画面から直接保存する。検出中は写真をぼかして保存を無効にし、一部の検出に失敗した状態で保存する場合は確認する。

番号候補の枠は、OCRが返した番号部分の文字矩形に文字高さの15%（最低2px）の余白を加えて作る。Visionなどが単語単位で座標を返した場合は、ラベルまで隠れることがある。OCRの読み落とし、離れた行に分かれた番号、短縮番号や内線は見落とす場合がある。番号が実在するかは調べていない。

## 実装と検証

- `JapaneseAddressDetector.detect` が同じOCR呼び出しから住所と番号の候補を返す。番号の種類は `CandidateKind.phone`、初期選択の判定は `PhoneNumberCandidate.automaticallySelected` に持たせる。`japaneseAddressCandidates` の住所判定と地名辞書は従来どおり。
- OCR用のネイティブコードやパッケージの追加はない。`ios/Podfile.lock` は、#56 で削除された依存パッケージに合わせて更新する。
- 単体・ウィジェットテストでは、数字列の判定、隣接するOCR枠の結合、設定の反映、再検出と取り消し、直接保存に渡す範囲を確認する。
- Androidの端末テストでは、既存配送ラベルと合成画像を使い、実OCR、編集、写真ライブラリへの保存を確認する。保存JPEGは、OCR枠とは独立した描画座標でも検査する。

ルール変更前の画像と検証結果は[2026-11-17の検証資料](evaluation-evidence/2026-11-17-phone-numbers/README.md)に記録している。
