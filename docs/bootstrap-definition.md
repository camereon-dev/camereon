# 起動・検証・Android 配布の定義

今回の実装範囲。プロダクト全体の [MVP 定義書](mvp-definition.md) に対して、最初の基盤を作る。

## 作るもの

- Flutter で iOS・Android のプロジェクトを作り、共通の起動画面を表示する。
- 起動画面にアプリ名、コンセプト、端末内で処理する方針を載せる。
- 「このアプリについて」から説明を開き、起動画面に戻れる。
- 撮影・編集機能は今後追加することを表示する。カメラや写真の権限はまだ求めない。
- フォーマット、静的解析、widget test、両 OS の起動を確認する integration test を用意する。
- GitHub Actions でテスト・ビルドし、Android のデモ APK を取得できるようにする。
- 別メンバーが起動、テスト、Android 配布を再現できる手順を用意する。

## デプロイの意味

今回は、インストールできる Android APK をビルドし、GitHub Actions の成果物からチームへ配布できることをデプロイとする。
iOS は Simulator でビルド・起動確認までとする。iOS 配布、ストア公開、撮影、画像加工、保存は次の段階に進める。

## 完了条件

- [x] Android の Emulator または実機でアプリが起動し、コンセプトが表示される。
- [ ] iPhone Simulator または実機でアプリが起動し、同じコンセプトが表示される。
- [ ] 両 OS で説明を開閉し、起動画面へ戻れる。
- [x] 小さい画面・文字拡大時でも操作でき、レイアウト例外が出ない。
- [x] フォーマット確認・静的解析・widget test が成功する。
- [ ] CI の Android・iOS 起動テストとビルドが成功する。
- [x] デモ APK を作れ、Android にインストールして通常起動できる。
- [ ] CI から Android APK を取得できる。
- [x] README に環境準備、起動、テスト、配布、ユーザー側の準備が書かれている。

証拠と未確認項目は [検証記録](verification.md) に記載する。
ビルドだけでは起動確認済みにしない。widget test だけでは OS 上での起動確認済みにしない。
